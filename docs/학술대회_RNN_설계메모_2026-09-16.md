## 1. 참외 연구에서 그대로 가져올 것

### 1.1 논문 구조 — 이게 제일 큰 수확

참외 연구의 뼈대는 **"같은 대상을 3D와 2D로 각각 측정하고, 실측을 기준으로 둘을 비교"** 다.
밀도 예측에서 R² 0.93(3D) vs 0.50(2D)이라는 한 줄이 논문 전체를 지탱한다.

우리도 같은 뼈대를 쓰되 **시계열로 확장**한다. 참외 연구는 컨베이어 위 1회 촬영이라 시간축이 없다.
**시간축이 우리가 더하는 부분이고, 그게 발표의 새로움이다.**

| | 참외 연구 | 이 연구 |
|---|---|---|
| 촬영 | 1회 (선별 시점) | 시계열 (격일) |
| 질문 | 이 과일은 정상인가 | **이 과일은 언제 수확하나** |
| 비교축 | 3D vs 2D | 3D 시계열 vs 2D 시계열 |
| 모델 | 회귀·분류 | RNN |

### 1.2 처리 파이프라인 — 과실에 한해 그대로 차용

```
과실 점군 → 다운샘플링 → 메시 → 부피
           → PCA 주축   → 장축 길이
```

**이건 설계 변경이다.** 기존 설계는 개체 전체를 점군으로만 유지하고 메시를 만들지 않기로 했는데,
그 판단은 **개체 전체**에 대해서만 옳다. 개별 과실은 참외와 같은 닫힌 볼록체이므로 메시가 맞다.

| 대상 | 표현 | 이유 |
|---|---|---|
| 개체 전체 | 점군 유지 | 열린 곡면, 얇은 잎. 메시화하면 잎 사이 공간이 메워짐 |
| **개별 과실** | **점군 → 메시** | 닫힌 볼록체. watertight 부피가 나옴 |
| 개별 잎 | 점군 + 국소 평면 적합 | 표면적만 필요 |

**PCA 주축 장축 길이**는 기존 `fruit_diameter` 정의보다 낫다. 회전에 불변이고 측정 방향을 고를 필요가 없다.

### 1.3 지표 — 계산식과 검증된 성능이 함께 있음

| 지표 | 정의 | 참외 연구 성능 | 이 연구에서의 쓰임 |
|---|---|---|---|
| 장축 길이 | PCA 제1주축 max−min | R² 0.973, RMSE 1.91 mm | RNN 입력 |
| 부피 | 메시 부피 | R² 0.998, RMSE 3.44 cm³ | **RNN 입력 + 타깃** |
| 밀도 | 무게 ÷ 부피 | R² 0.929, RMSE 9.34 kg/m³ | 충실도 |
| Ellipsoidality | 부피 ÷ 외접 타원체 부피 | Acc 89.3, F1 89.5 | 기형과 판별 |
| 상/하 부피비 | 장축 반분한 두 영역 부피비 | **Acc 94.7, F1 96.6** | 기형과 판별 |

**Crop Pack의 `FRUIT_CULL_DEFECTIVE` 규칙에 판정 방법이 비어 있었는데 여기가 채워진다.**
문헌 추정값이 아니라 정확도가 붙은 지표이므로 `confidence`를 높게 줄 수 있다.
`source`는 이 자료를 정확히 인용한다 (출처 확인 필요).

### 1.4 실측 프로토콜 — 그대로 차용

- 버니어캘리퍼스 → 길이
- 저울 → 무게
- **물치환법 → 부피, 밀도**
- 개체당 3반복 촬영

**물치환법이 현재 기록 체계에 빠져 있다.** 3D 부피를 검증할 유일한 수단인데
`manual_measurements.csv`에 과실 부피 항목이 없다. §3에서 보완한다.

### 1.5 색 채널 선택 — 부분만 차용

참외 연구는 Lab의 b 채널에서 Otsu 이진화로 과실을 분리했다. 참외가 노란색이라 b 채널이 잘 먹었다.

토마토는 다르다. 성숙 과실은 붉으므로 **a 채널**이, 잎은 녹색이므로 a 채널 음수 방향이 유효하다.
다만 **배경·판 제거에는 색을 쓰지 않는다** — 그건 기하로 한다(`CONVENTIONS.md` §3).
색 채널은 **이미 식물로 분리된 영역 안에서 과실과 잎을 가르는 데만** 쓴다.

## 2. RNN 설계

### 2.1 예측 단위는 개체가 아니라 과실

화방마다 개화 시기가 다르므로 한 개체 안에 성숙 단계가 섞인다. 개체 평균을 쓰면 그게 전부 뭉개진다.

**3D가 여기서 기여한다.** 과실 단위 3D 추적이 되므로 "이 과실"의 성장곡선을 입력할 수 있다.
2D로는 며칠 지나면 어느 과실이 어느 과실인지 매칭이 무너진다.

### 2.2 입력 피처

**과실 시계열** (매 세션, 과실 ID별)

| 피처 | 출처 |
|---|---|
| `fruit_volume_mesh` | §1.2 메시 |
| `fruit_major_axis_mm` | PCA 주축 |
| `fruit_ellipsoidality` | §1.3 |
| `fruit_volume_ratio` | §1.3 |
| `fruit_L`, `fruit_a`, `fruit_b` | 색보정 후 CIELab |
| `days_since_fruit_set` | `manual_events.csv` |
| `truss_index`, `node_index` | 절위 그래프 |
| `observation_status` | observed / inferred / unknown |
| `uncertainty` | 2뷰 운영 시 필수 (§2.5) |

**환경 시계열** (연속 로그에서 집계)

| 피처 | 산출 |
|---|---|
| 평균·최고·최저 기온 | 구간 집계 |
| **DIF** (주야 온도차) | 주간평균 − 야간평균 |
| **누적 GDD** | 착과일부터 |
| **누적 DLI** | PPFD × 일장 적분 |
| 저면 양액 EC, pH | 구간 평균 |

**시간 간격** `delta_t_days` 를 입력에 명시적으로 포함한다. 촬영이 불규칙해질 수 있고,
RNN은 간격을 스스로 모른다.

### 2.3 출력

- 1순위: **수확까지 남은 일수**
- 2순위: 도달 질량 (수확 시 실측이 정답)
- 둘 다 **불확실도와 함께** 출력

정답 라벨은 `manual_events.csv` 의 `fruit_harvest` 행이다. 수확 판단 기준(색 기준)은 사용자가 정한다.

### 2.4 구조

- 데이터가 적다. **GRU 1~2층, hidden 32~64** 수준에서 시작. Transformer는 이 규모에서 과적합한다.
- 과실을 샘플로 보고 pooling. 개체별 개별 학습은 불가능하다.
- **분할은 개체(plant_id) 단위.** 같은 개체의 모든 과실·모든 날짜는 같은 split.
  과실 단위로 나누면 같은 개체의 형제 과실이 train/test에 흩어져 누수가 된다.

### 2.5 2뷰 운영 시 주의

최종 운영에서는 2뷰 모델이 표현형을 추정하고 그 결과가 RNN 입력이 된다.
**추정 오차가 시계열 노이즈로 들어가고, RNN이 그걸 진짜 생육 변화로 착각한다.**

→ 2뷰 모델의 `uncertainty`를 RNN 입력 피처로 함께 넣는다. 두 모델이 직렬이므로
이걸 안 하면 뒤에서 조용히 망가진다.

발표 단계에서는 36뷰 3D 값을 직접 쓰면 되므로 이 문제가 없다. **운영으로 갈 때의 항목**으로 남긴다.

## 3. 추가로 기록해야 할 것 — 현재 체계에 빠져 있음

### 3.1 수확 시 파괴 측정 (신규)

수확한 과실마다 그 자리에서 잰다. **이때 안 재면 영영 못 잰다.**

`manual_measurements.csv` 에 trait 추가:

| trait | 도구 | 단위 |
|---|---|---|
| `fruit_mass_harvest` | 저울 | g |
| `fruit_volume_water` | **물치환법** | cm³ |
| `fruit_major_axis_caliper` | 캘리퍼스 | mm |
| `fruit_density_measured` | 무게 ÷ 부피 (유도) | kg/m³ |

`subject_id` 에 과실 ID를 적어 3D 추정값과 1:1로 대조할 수 있게 한다.

### 3.2 환경 로그는 개체별이 아니라 구역별 연속 로그 (스키마 변경)

두 가지를 동시에 고친다.

**(a) 개체별이 아니다.** 12개체가 같은 환경에서 자라므로 환경 로그는 **환경 1개당 1개**다.
현재 스키마의 `plant_id` 키는 잘못됐다. 같은 값을 12줄씩 복사하게 되고, 그중 한 줄만 고쳐지면
어느 것이 맞는지 알 수 없게 된다.

→ `plant_id` 를 **`zone_id`** 로 바꾼다. 경로도 개체 폴더 밖으로 뺀다.

```
data/records/_environment/<zone_id>.csv
```

**(b) 세션당 1행이 아니라 매일 기록이다.** 격일 촬영이면 그 사이 48시간의 온도·광량을 모르므로
**GDD·DLI를 계산할 수 없다.**

**확정: 하루 3회 수기 기록.** 시각을 고정한다.

| # | 시각 | 무엇을 대표하나 |
|---|---|---|
| 1 | **점등 직후** | 일 최저 온도 근사 (야간이 막 끝난 시점) |
| 2 | **광기 중간** | 일 최고 온도 근사 |
| 3 | **소등 직전** | 주간 종료 온도 |

야간은 직접 측정하지 않는다. **3회차와 다음 날 1회차 사이가 야간**이므로, 두 값의 평균을
야간 평균으로 근사한다. 이걸로 DIF가 계산된다.

#### 3회로 무엇이 계산되는가

| 값 | 계산 | 3회로 충분한가 |
|---|---|---|
| **GDD** | (Tmax + Tmin)/2 − Tbase | **충분** — 표준식이 최고·최저만 쓴다. 1회차가 Tmin, 2회차가 Tmax |
| **DIF** | 주간평균 − 야간평균 | 충분 — 야간은 위 근사 |
| **DLI** | PPFD × 일장 × 3600 / 10⁶ | **매일 잴 필요 없음** (아래) |

#### DLI는 매일 재지 않는다

LED는 광기 동안 PPFD가 일정하다. 그러므로

```
DLI (mol·m⁻²·d⁻¹) = PPFD (µmol·m⁻²·s⁻¹) × 일장(h) × 3600 / 1,000,000
```

**위치별 PPFD 1회 실측 + LED 스케줄**이면 DLI가 정확히 나온다.
PPFD는 조명을 바꾸거나 개체를 옮겼을 때만 다시 잰다.

#### 항목별 빈도 — 3회 전부를 다 잴 필요는 없다

| 항목 | 빈도 |
|---|---|
| `air_temp`, `rh` | **하루 3회** |
| `solution_ec`, `solution_ph`, `bottom_water_level` | **하루 1회 (점등 직후)** — 상시저면이라 하루 안에 급변하지 않고, 증발로 서서히 농축되므로 같은 시각이 중요하다 |
| `ppfd`, `photoperiod` | 변경 시에만 |

> **권장: 온습도 데이터로거를 하나 산다.** 2만 원 내외의 USB 로거면 온습도가 자동으로
> 시간당 기록되고, 이 항목이 통째로 사라진다. 45일 × 3회 = 135회를 손으로 적으면
> 빠뜨리는 날이 반드시 생기고, **온도는 소급 기록이 불가능하다.**
> EC·pH·수위는 어차피 수기이므로 하루 1회만 남는다.

**(c) 위치 차이는 별도 표로 한 번만 잡는다.** 같은 선반이어도 가장자리와 중앙은 광량이 다르다.
개체마다 환경 로그를 따로 만드는 대신, 위치와 그 지점의 PPFD를 **한 번** 실측해 둔다.

`data/records/plant_positions.csv`

| 컬럼 | 설명 |
|---|---|
| `plant_id` | |
| `zone_id` | 어느 환경 로그를 따르는가 |
| `shelf_row`, `shelf_col` | 선반 위치 |
| `ppfd_at_position` | 그 지점 캐노피 높이 실측 PPFD |
| `measured_at` | |

RNN 입력에서 광량은 `zone` 로그의 PPFD에 이 개체별 계수를 곱해 쓴다.
위치를 바꾸면 행을 추가한다 — **덮어쓰지 않는다.**

**(a)(b)는 지금 고쳐야 한다.** 소급이 불가능한 유일한 항목이다.

### 3.3 착과일 (기존 항목, 중요도 상향)

`manual_events.csv` 의 `fruit_set` 이 `days_since_fruit_set` 의 기준점이다.
지금까지는 참고 항목이었지만 RNN에서는 **핵심 입력**이 된다. 빠뜨리면 그 과실은 학습에 못 쓴다.

## 4. 발표 구성안

1. 배경 — 실내 재배에서 수확 적기 판단의 어려움
2. 관련 연구 — 참외 연구의 3D vs 2D 결과 인용, **단일 시점의 한계** 지적
3. 방법 — A4 ChArUco + 회전판 + 스마트폰 1대 저비용 리그, 36뷰 복원, 과실 단위 추적
4. 결과 1 — **복원 정확도**: 뷰 수 스윕(8/12/18/36) × 실측 대비 오차
5. 결과 2 — **3D vs 2D 시계열 RNN 비교** ← 핵심 표
6. 결과 3 — 형상 지표 기반 기형과 판별 (참외 연구 지표의 토마토 적용)
7. 처리 시간
8. 한계와 향후 — 2뷰 증류

> **4번은 RNN이 안 되어도 남는 결과다.** 발표가 RNN 성공 여부에 전부 걸리지 않도록
> 복원 정확도 검증을 독립된 결과로 세워둔다.
