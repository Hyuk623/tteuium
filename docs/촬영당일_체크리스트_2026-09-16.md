## 2. 사진 정리 — 촬영 직후 5분

### 2.1 카메라에서 옮기기

```
data/raw/<plant_id>/<session_id>/images/
  side_000.jpg ... side_035.jpg      회전 순서대로 (0°부터)
  top_T0.jpg ... top_T4.jpg
  empty_rig.jpg                      식물 없이 찍은 1장
```

`session_id` = `<plant_id>_<YYYYMMDD>_<HHMM>` 예: `DT-001_20260920_1030`

**손으로 이름을 바꾸지 말 것.** `tools/make_session.py`가 EXIF 촬영시각 순서로 정렬해 자동으로 붙인다. 손으로 바꾸면 회전 순서가 어긋나도 알아챌 방법이 없다.

### 2.2 도구가 자동으로 막아주는 것

`make_session.py`는 아래를 발견하면 **아무것도 쓰지 않고 멈춘다.**

- 장수가 42장이 아님
- 프레임마다 **ISO·초점거리가 다름** → 카메라가 자동 모드였다는 뜻. 그 세션은 쓸 수 없다
- 읽히지 않는 파일, 중복 타임스탬프

세 번째 항목이 실무에서 제일 자주 걸린다. 촬영 시작 전에 수동 고정을 반드시 확인한다.

### 2.3 그 자리에서 눈으로 볼 것

- 42장 중 흔들린 것, 초점 나간 것이 없는지
- 상면 T0에서 **판이 식물에 다 가려지지 않았는지**
- 측면에서 판 앞쪽 테두리가 보이는지
- 기준 블록과 컬러차트가 매 장 프레임 안에 있는지

여기서 걸리면 **그 자리에서 다시 찍는다.** 식물은 내일 다른 모습이 된다.

## 3. 사람이 손으로 적는 것

### 3.1 `manual_measurements.csv` — 매 세션 필수

경로: `data/records/<plant_id>/manual_measurements.csv`

| trait | 도구 | 단위 | 비고 |
|---|---|---|---|
| `plant_height` | 자 | mm | 배지 표면 ~ 생장점. 줄기를 펴지 말고 자연 상태 |
| `stem_diameter_base` | 캘리퍼스 | mm | 자엽절 바로 위. 매번 같은 높이 |
| `leaf_count` | 눈 | count | **전개된 잎만.** 기준을 한 번 정하고 끝까지 유지 |
| `truss_count` | 눈 | count | 화방 수 |
| `fruit_count` | 눈 | count | 착과된 것만 |
| `canopy_width` | 자 | mm | 가장 넓은 방향 |
| `reference_block_height` | 캘리퍼스 | mm | **블록은 안 변하지만 매 세션 기록.** 복원 오차 산출의 기준선 |

- 촬영 **직후** 잰다. 몇 시간 뒤면 다른 값이 된다
- `observer`에 이름을 적는다. 사람이 바뀌면 엽수 기준이 달라진다
- 못 잰 항목은 **행을 빼지 말고** `value`를 비워 `unavailable`로 남긴다

### 3.2 `manual_events.csv` — 일어난 날만

| event_type | 언제 적나 |
|---|---|
| `flower_bud` | 봉오리 확인 |
| `flowering_open` | **화관이 젖혀져 정면에서 노랗게 보이는 날** |
| `flower_spent` | 화판 탈락 |
| `fruit_set` | 착과 확인 |
| `fruit_color_break` | 착색 시작 |
| `fruit_harvest` | 수확 |
| `leaf_removed` | 잎을 뗀 날 — **반드시 적는다** |
| `organ_lost` | 부러짐·떨어짐 |
| `anomaly` | 그 외 이상 |

`truss_index`(아래부터 1)와 `node_index`(자엽절 0)를 같이 적는다. 이 두 숫자가 3D 절위 그래프와 대조되는 유일한 연결고리다.

**`leaf_removed`를 빠뜨리면 시계열 추적이 그 잎을 "갑자기 사라짐 = 추적 실패"로 기록한다.** 뗀 날은 꼭 남긴다.

### 3.3 환경 기록 — 개체별이 아니라 구역별, 하루 3회

경로: `data/records/_environment/<zone_id>.csv` (개체 폴더 밖)

12개체가 같은 환경이면 **환경 로그는 1개다.** 개체마다 복사하지 않는다.

| 시각 | 재는 것 |
|---|---|
| 점등 직후 | 온도·습도 + **EC·pH·저면수위** |
| 광기 중간 | 온도·습도 |
| 소등 직전 | 온도·습도 |

PPFD와 일장은 변경 시에만. 위치별 PPFD는 `data/records/plant_positions.csv` 에 1회 실측.

자세한 근거와 GDD·DLI 계산은 `docs/학술대회_RNN_설계메모_2026-09-16.md` §3.2.

#### 원래 스키마

| 컬럼 | 단위 | 어디서 |
|---|---|---|
| `air_temp` | °C | 센서 |
| `rh` | % | 센서 |
| `solution_ec` | dS/m | **저면 양액에서.** 측정 지점을 세션 간 바꾸지 않는다 |
| `solution_ph` | – | 저면 양액 |
| `ppfd` | µmol·m⁻²·s⁻¹ | 캐노피 높이에서 |
| `photoperiod` | h | LED 스케줄 |
| `bottom_water_level` | – | `full` / `low` / `refilled` |

- `source`에 `sensor` / `manual` 을 구분해 적는다
- 양액을 보충하거나 교체한 날은 `note`에 남긴다

### 3.4 `organ_label_map.csv` — 파이프라인 결과가 나온 뒤

사람이 붙인 이름(`T2-F3`)과 파이프라인이 붙인 ID(`fruit_014`)를 연결하는 표다.

**이 표가 없으면 "개화 탐지 정확도"를 계산할 수 없다.** 촬영 당일이 아니라 Stage 3~4가 돌아간 뒤 채운다. 파일럿부터 만든다.

## 4. 촬영 당일 순서

```
[ ] 재배 LED 끄고 촬영용 백색 조명 켜기
[ ] 카메라 수동 고정 — ISO / 셔터 / 초점 / WB / 줌 1× 메인
[ ] HDR·장면최적화·AI 보정 전부 끄기
[ ] 시험 촬영 1장 → EXIF 초점거리·ISO 확인
[ ] 빈 리그 1장 (식물 없이)
[ ] 화분·기준블록·컬러차트 배치
[ ] 측면 36장 — 각도 눈금 맞추고 5초 대기 후 셔터
[ ] 상면 T0~T4 5장
[ ] ── 촬영 끝, 여기서부터 기록 ──
[ ] manual_measurements.csv 7항목
[ ] manual_events.csv (일어난 게 있으면)
[ ] environment.csv 1행
[ ] 사진 42장 옮기고 make_session.py 실행
[ ] 도구가 뱉은 경고 확인 — ISO/초점거리 불일치가 없는지
[ ] records.py validate 실행
```

## 5. 자주 나는 사고

| 사고 | 결과 | 예방 |
|---|---|---|
| 카메라 자동 모드 | 세션 전체 폐기 | 시험 촬영 EXIF 확인 |
| `board_variant_id`를 5×5로 잘못 적음 | **검출 정상, 모든 치수 40% 오류** | `--board-variant` 필수 인자 |
| 실측을 나중에 함 | 다른 값이 됨 | 촬영 직후 그 자리에서 |
| 적엽하고 기록 안 함 | 추적이 "실종"으로 기록 | `leaf_removed` 행 |
| 촬영 시각이 들쭉날쭉 | 잎 각도 변화가 생육 신호로 오독 | 매번 같은 시각 ±1시간 |
| 물 준 직후 촬영 | 물방울 반사 + 잎 각도 변화 | 관수 후 1시간 이상 |
| 기준 블록 높이 기록 누락 | 그 세션의 복원 오차를 못 구함 | 매 세션 기록 |

## 6. 아직 안 정해진 것

- `scale_block_nominal_height_mm` — 블록을 캘리퍼스로 재서 `config/board_spec.json`에 넣어야 한다. 현재 `null`
- `physical_print_verified` — 인쇄물을 실측한 뒤 `true`. 현재 `false`
- 재배 LED 색온도 — 보라색 계열이면 촬영용 백색 조명이 필수 항목이 된다
- 회전판 지름 — 각도 눈금 띠는 300 mm 기준으로 만들어져 있다
