# phynotype2 — 상면 시계열 사진의 복엽·터미널 리프 추적 설계 (2026-10-10)

구현 계약(영어, Codex용): `handoff/CODEX_PROMPT_PHYNOTYPE2_COMPOUND_TERMINAL_TRACKING_2026-10-10.md`
구현 위치: `phynotype2/` (2026-10-10 사용자 결정). 지금은 설계만 있고 코드는 없습니다.

## 1. 무엇을 하는가

같은 식물을 하루 2회 위에서 찍은 사진만으로,

1. 사진마다 **복엽**과 그 끝의 **터미널 리프(정단 소엽)**를 구분하고, 터미널 리프를 소속 복엽에 연결합니다.
2. 날짜가 바뀌어도 같은 복엽에 같은 `track_id`를 유지합니다. 터미널 리프는 소속 복엽의 ID를 따라갑니다.
3. 겹침·가림·분할 실패로 모양이 불분명한 복엽은 기존 가상식물 생성기로 **후보 형태 여러 개**를 만들어 보완합니다.
4. 결과는 "사진으로 본 부분"과 "생성기로 추정한 부분"을 나눠 다음 단계(구조 갱신)에 넘깁니다.

나머지 측소엽의 개별 ID는 이번 범위가 아닙니다.

## 2. 복엽·터미널 리프 구분과 소속

- **터미널 리프의 정의**: 엽축 끝에 짝 없이 달린 소엽입니다.
- **판정 근거**: 사람 라벨 > 검토된 검출기 > 기하 제안 순으로 우선합니다. 기하 제안은 "복엽 주축의 가장 먼 쪽, 반대편 짝이 없는 소엽"이고, 제안일 뿐입니다.
- **판정 상태**: 확인 / 제안 / 안 보임(엽축 끝이 가려짐) / 판정 불가. 생성기로 터미널 리프를 "찾아내지" 않습니다.
- **소속 연결**: 두 복엽 마스크에 걸치거나 어디에도 안 걸치면 `unassigned`로 둡니다. 가장 가까운 복엽에 억지로 붙이지 않습니다.

## 3. 날짜 간 추적

- **좌표 기준**: 보드가 없으므로 화분 테두리로 중심과 척도(mm/px)를 잡고, 화분 방향 표시로 회전을 맞춥니다. 방향 표시가 없으면 방위 단서는 끄고, 회전에 무관한 단서만 씁니다.
- **단서**: 아래 단서를 쌍마다 모두 기록합니다.
  - 위치: 터미널 끝의 방위·거리, 복엽 기부 방위
  - 형태: 터미널 리프 윤곽, 복엽 윤곽
  - 외관: 기존 `leaflet_chain_match` 방식의 SIFT 특징 일치
  - 배열: 줄기 둘레 순서가 보존되는지
- **매칭**: "매칭 없음" 선택지를 넣은 헝가리안 할당을 씁니다. 비교 대상은 직전 사진만이 아니라 살아 있는 모든 추적입니다(재등장 대비).
- **가중치·임계값**: 근거가 없으므로 비워 둡니다. 비어 있는 동안 모든 연결은 **제안**으로만 나오고 사람이 확인합니다. 사람 판정이 충분히 쌓이면(기존 규칙: 클래스당 30건 이상) 그때 임계값을 맞춥니다.
- **오전·오후 사진**: 광주기상 시점이 달라 잎 자세가 다를 수 있습니다. 그래서 점등 후 경과 시간을 기록하고, 같은 시간대끼리의 비교도 함께 봅니다.

**상태 6가지** (사진마다, 추적마다 한 줄)

| 상태 | 뜻 | 주의 |
|---|---|---|
| 계속 관측 `continued` | 직전에도 지금도 보임 | |
| 미관측 `unobserved` | 추적은 살아 있으나 지금 안 보임 | 사유: 가림 / 미검출 / 화면 밖 / 모름. **낙엽·사망이 아님** |
| 재등장 `reappeared` | 안 보이다가 다시 연결됨 | 공백 횟수를 기록 |
| 첫 관측 `first_observed` | 기존 추적과 연결 안 됨 → 새 추적 | **발생일이 아님**. "이전 촬영 이후 ~ 이번 촬영" 구간으로만 표시 |
| 제거 확인 `removal_confirmed` | 추적 종료 | 사람 기록(`manual_events.csv`의 `leaf_removed`·`organ_lost`)이 있을 때만 |
| 모호 `ambiguous` | 후보가 경합하거나 분할·병합이 미해결 | 새 ID를 주지 않음 |

**분할 오류 처리**
- 한 잎이 여러 조각으로 잡히면 `fragment_suspect`, 여러 잎이 하나로 합쳐지면 `merge_suspect` 이벤트를 남깁니다. 자동으로 고치지 않고 검토 페이지에서 사람이 판정합니다.
- **ID는 절대 다시 매기지 않습니다.** 수정은 이벤트로 남고, 그 사진 이후를 새 실행 폴더에서 다시 계산합니다.

## 4. 불분명한 복엽 — 생성기 후보

**생성기 확인 결과**
- 재사용: 복엽 내부 생성 `build_compound`, 소엽 메시, 윤곽 풀
- 바꿔야 하는 점:
  - 생성기는 관측을 조건으로 받지 못합니다(무작위 생성 + 기각 방식).
  - 렌더링은 보드 자세가 필요합니다.
  - 모든 생성 범위가 `user_assumed`이고, 사실성 기준(C6)도 아직 통과하지 못했습니다.
- 그래서 생성기는 고치지 않고, `phynotype2`에 다음을 새로 만듭니다.
  - 관측으로 생성기 입력을 만드는 어댑터
  - 상면 투영기(정사영)
  - 점수 계산

**절차**
1. 보이는 복엽 마스크, 보이는 터미널 리프 윤곽, 이전 사진의 더 잘 보였던 모습, 척도를 모읍니다.
2. 2D를 3D로 올립니다.
   - 관측에서 가져오는 값: 방위, 보이는 축 길이
   - 생성기 가정 범위에서 뽑는 값: 높이, 기울기
   - 값마다 출처 표시를 붙입니다.
3. 여러 시드로 후보를 생성하고 위에서 본 모습으로 투영합니다.
4. 걸러냅니다.
   - **보이는 픽셀을 전부 덮지 못하는 후보는 버립니다.**
   - 배경에 침범한 정도와 터미널 윤곽 차이는 점수로 기록합니다.
5. 상위 몇 개를 **모두 유지**하고 하나로 확정하지 않습니다. 순위는 확률이 아닙니다.
6. 결과 형상은 관측(사진 그대로) / 생성(관측 밖 보완) / 충돌(후보 폐기)로 영역을 나눠 표시합니다.
7. 나중 사진에서 그 부분이 보이면, 이전 후보와 새로 드러난 영역의 일치도를 기록합니다. 이전 후보 파일은 고치지 않습니다. 사진 간격이 길면 "생장 혼입"으로 따로 표시합니다.

**하지 않는 것**
- 생성된 잎을 새 잎 발생이나 정답으로 기록하지 않습니다.
- 생성된 형상을 P3에 `observed_axis`로 넘기지 않습니다.
- 척도를 모르면 생성 자체를 하지 않습니다.

## 6. 검증

- **사람 정답**: `manual_track_labels.csv`를 사람이 작성합니다. 사람 이름과 파이프라인 ID는 섞지 않습니다.
- **지표**
  - ID 오류: 교체·조각남·합쳐짐 횟수
  - 가림 후 재연결률: 공백 길이별
  - 첫 관측 판정의 정밀도·재현율: 발생일 지표가 아님
  - 소속 정확도: 미배정 비율 포함
  - 생성 후보 대 후속 관측: 새로 드러난 영역 IoU, 터미널 끝 오차, 후보 집합 적중률을 기준선(지난 모습 그대로 / 보완 없음)과 비교
- **분할**: 개체 단위, 시간 순방향으로 나눕니다.
- **합격 기준**: 이 문서에서 정하지 않습니다. 결과를 보기 전에 사용자가 정합니다.
- **시험 자료**

| 자료 | 시험할 수 있는 것 |
|---|---|
| 1주차 반복 촬영쌍 | 변화 없음 → ID가 바뀌면 오류. 단서별 잡음 하한도 측정 |
| 식물 1 순차 제엽 | 같은 날 가림 변화, 제거 확인 경로 |
| 밀도 코호트 1일 2회 시계열 | 본 시험 |
| dwt_01–04 | 사용자 승인 시에만 선택 검증 |
| 생성기 합성 시퀀스 | 코드 시험용. 정확도 주장에는 쓰지 않음 |

## 7. 선행연구와 적용 범위 (원문 확인 2026-10-10)

| 연구 | 하는 일 | 우리에게 적용되는 범위 |
|---|---|---|
| LeafTrackNet (arXiv 2512.13130) | 카놀라, 24시간 간격, 외관 임베딩만으로 추적 | 매칭 장치만 참고합니다. 10/8 기록의 수치는 원문과 달라 미검증 상태입니다. |
| LeTra (Plant Methods 2024) | 애기장대 형광 영상, 약 8시간 간격, IoU 매칭 | 프레임을 놓치거나 주야 움직임이 크면 실패한다는 교훈 |
| Heiwolt et al. (arXiv 2209.11526) | 토마토 3D, 약 2일 간격, 윤곽 형태 매칭 | 윤곽이 위치보다 강한 단서라는 근거 |

네 편 모두 "복엽 + 터미널 2수준, 상면 RGB" 추적은 하지 않습니다. 따라서 성능 목표로 삼을 수치는 없습니다.
