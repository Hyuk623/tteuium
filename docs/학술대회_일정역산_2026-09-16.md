## 1. 결론부터

45일 안에 원래 설계를 다 하는 것은 불가능하다. **두 가지를 바꾸면 가능하다.**

1. **RNN의 과제를 "수확일 예측"에서 "다음 시점 상태 예측"으로 바꾼다** — 라벨이 공짜가 된다

## 2. 첫 번째 벽 — 수확 이벤트를 관측할 시간이 없다

수확일 예측 RNN의 정답 라벨은 **실제 수확일**이다. 그런데 방울토마토는 개화에서 수확까지
대략 **45~60일**이 걸린다 (품종·온도 의존. 정확한 값은 사용자 확인 필요).

오늘 개화 중인 개체로 시작하면 **수확은 11월 이후**다. 마감 뒤다.

### 대응

| 방안 | 판단 |
|---|---|
| 이미 착과된(녹숙과가 달린) 개체를 구해 시작 | **필수.** 착색기까지 7~14일이라 관측 가능 |
| 개화만 있는 개체 | 이번 발표에는 못 씀 |
| 여러 성숙 단계를 섞어 구매 | 권장 — 짧은 기간에 성숙 스펙트럼 확보 |

**착과된 개체 확보가 이 프로젝트의 임계 경로다. 오늘 주문하지 않으면 뒤가 전부 밀린다.**

---

## 3. 두 번째 벽 — 수확 이벤트 수가 너무 적다

3주 촬영에서 실제로 수확에 도달하는 과실은 개체당 몇 개 수준이다.
개체 12주라 해도 3주 안에 수확에 도달하는 과실은 개체당 몇 개다. **60~120개 시퀀스**,
각 10스텝 남짓. GRU로도 과적합 위험이 크다.

### 대응 — 과제를 바꾼다

**"다음 시점 과실 상태(부피·색) 예측"** 으로 바꾸면 라벨이 공짜가 된다.

- 세션 쌍이 전부 학습 샘플이 된다. 수확을 기다릴 필요가 없다
- 12개체 × 20과실 × 10세션 = **2,000개 이상의 (t → t+1) 샘플**
- 수확일 예측은 **파생 결과**로 붙인다: 예측된 색 궤적이 수확 기준 색에 언제 도달하는가
- 관측된 수확 이벤트는 그 파생 예측의 **검증용**으로 쓴다 (적은 수로도 검증은 가능)

발표에서의 주장이 이렇게 바뀐다.

| | 전 | 후 |
|---|---|---|
| 주 과제 | 수확일 회귀 | **과실 상태 시계열 예측** |
| 라벨 | 실제 수확일 (희소) | 다음 세션 관측값 (풍부) |
| 수확일 | 주 결과 | 파생 + 소수 사례 검증 |
| 비교축 | 3D vs 2D 입력 | 동일 |

**3D vs 2D 비교는 그대로 유지된다.** 논문의 핵심 표는 여전히 그것이다.

## 4. 세 번째 벽 — Stage 3(기관 분할)이 제때 안 된다

RNN은 과실 단위 추적을 전제한다. 그런데 Stage 3은 이 프로젝트에서 가장 어려운 단계이고,
잎 인스턴스 분할과 다시점 병합은 45일 안에 신뢰할 수준이 안 될 가능성이 높다.

### 대응 — 과실만 한다

| | 난이도 | 이번 발표 |
|---|---|---|
| 과실 | 낮음 — 붉고 둥글고 볼록, 개수 적음 | **포함** |
| 잎 | 높음 — 얇고 서로 겹침, 개수 많음 | 제외 |
| 절위 그래프 | 높음 | 제외 |
| 적엽·적과 위치 | 높음 | 제외 |

과실은 색과 형태가 뚜렷해 분할이 쉽고, 개체당 수십 개라 **틀린 것을 사람이 손으로 고치는 것도 현실적**이다.
잎은 수백 장이라 불가능하다.

잎·절위·적엽은 발표의 "향후 계획"으로 넘긴다. 제품 목표가 줄어드는 것이 아니라 **발표 범위만** 줄인다.

## 4b. 개체 12주 — 촬영 시간이 새로운 제약이 된다

개체가 12주라는 것은 통계적으로는 좋은 소식이다. 개체 단위 분할이 **8 train / 2 val / 2 test** 로
무리 없이 나온다. 그런데 촬영 시간이 걸린다.

| 뷰 수 | 개체당 | **12개체 총** | 실측·기록 포함 |
|---|---|---|---|
| 36뷰 | 약 13분 | 2.6시간 | **약 3.2시간** |
| 18뷰 | 약 10분 | 2.0시간 | 약 2.6시간 |
| 8뷰 | 약 7분 | 1.4시간 | 약 2.0시간 |

격일 11회면 36뷰 기준 **누적 35시간**이다. 3주 동안 이걸 감당할 수 있는지가 현실 문제다.

### 대응 두 가지 — 파일럿 결과를 보고 택한다

**(A) 뷰 수를 줄인다.** 파일럿 스윕에서 18뷰가 36뷰와 오차 차이가 작으면 18뷰로 간다.
하루 40분이 줄어든다. 파일럿의 목적이 원래 이것이다.

**(B) 역할을 나눈다.**

| | 개체 수 | 촬영 | 용도 |
|---|---|---|---|
| 3D군 | 6주 | 전체 뷰 + 2뷰 | **3D vs 2D 비교** (같은 개체에서 둘 다 나와야 비교가 성립) |
| 2D군 | 6주 | **2뷰만** (T0 + 측면 1장) | RNN 학습 시퀀스 수 확보 |

2뷰만 찍으면 개체당 1~2분이다. 6주 해봐야 10분이고, 3D군 6주는 1.3시간.
**총 1.5시간 내외로 떨어진다.**

(B)는 데이터 성격도 좋아진다. 3D vs 2D 비교는 3D군 안에서 성립하고,
RNN은 12개체 전부의 시계열을 쓴다. **시간을 줄이면서 샘플 수는 유지한다.**

권장: 파일럿 후 (A)로 뷰 수를 줄이고, 그래도 빠듯하면 (B)를 겹친다.

### 9/24 마감이 뜻하는 것

**7일 안에 Stage 2(복원)와 Stage 3의 과실 부분을 끝내야 한다.** 가능하되 조건이 있다.

| 조건 | 이유 |
|---|---|
| **촬영을 코드 완성 전에 시작한다** | 사진은 나중에 다시 처리할 수 있지만 그 주의 식물은 다시 오지 않는다. 9/20부터 찍기 시작하고, 코드는 그 사진으로 개발한다 |
| **잎은 건드리지 않는다** | 잎 인스턴스 분할은 7일에 안 된다. 과실만 (§4) |
| **과실 분할은 수동 보정을 전제로 한다** | 개체당 과실 수십 개다. 자동 분할이 70%만 맞아도 손으로 고치는 게 현실적이다. 잎이었으면 불가능하다 |
| **파일럿 결과를 기다리지 않는다** | 뷰 수 결정과 복원 구현을 병렬로 간다. 뷰 수는 나중에 부분집합으로 재계산하면 되므로 코드를 막지 않는다 |

### "착과기 시작 시 RNN 학습 시작"의 실제 의미

RNN은 한 번 학습하고 끝나는 게 아니라 **데이터가 쌓이는 대로 다시 학습**하게 된다.
착과기 초반에는 시퀀스가 3~4스텝뿐이라 성능이 안 나오는 게 정상이다. 이때의 목적은 성능이 아니라
**파이프라인이 끝까지 돌아가는지 확인**하는 것이다.

→ 착과기 진입 시점에 해야 할 일은 "학습을 시작한다"가 아니라
**"3세션치 데이터로 학습 스크립트가 에러 없이 끝까지 도는지 확인한다"** 이다.
여기서 막히면 10월 말에 발견하는 것보다 3주 이르다.

| 시점 | RNN 상태 | 목적 |
|---|---|---|
| 착과기 진입 (3~4세션) | 성능 안 나옴 | **배관 점검** — 입력 스키마·결측·학습 루프 |
| 6~7세션 | 추세 보이기 시작 | 피처 선택, 2D 베이스라인과 첫 비교 |
| 10~11세션 | 최종 | 발표용 결과 |

| RNN 성능이 안 나옴 | §7의 독립 결과가 남는다 |

### 7. 발표가 RNN에 전부 걸리지 않게

아래 두 결과는 **RNN과 무관하게** 촬영만 끝나면 나온다. 이걸 독립 장으로 세운다.

1. **저비용 리그의 복원 정확도 검증** — 뷰 수 8/12/18/36 × 실측 대비 오차
2. **과실 형질의 3D vs 2D 비교** — 부피·장축·밀도. 참외 연구와 같은 구조

RNN이 기대만큼 안 나와도 발표는 성립한다. 이 구조를 처음부터 잡아두는 것이 45일 일정의 핵심 안전장치다.
