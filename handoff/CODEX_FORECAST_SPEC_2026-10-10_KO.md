## 1. 결론부터 — 지금은 "조건부 시뮬레이션" 외에 가능한 것이 없습니다

요청서 §2-3이 "한 시점 사진으로 생장 속도를 안다고 가정하지 말 것" 이라 했는데, 실제 기록을 세어
보니 **한 시점조차 개체가 식별되어 있지 않습니다.**

| 항목 | 디스크 실태 |
|---|---|
| 같은 개체·같은 기관의 반복 관측 | **0건** — 기관 수준 날짜 1개, 두 번 관측된 기관 없음 |
| 식별된 개체 | **0개** — Micro-Tom 18개 슬롯이 등록돼 있지만 `plant_id` 칸이 전부 비어 있음 |
| 캘리퍼 실측 길이 | **1건** (50.71 mm, 복엽 1장, 1일, 개체 미식별) |
| 화방 관측 | **0건** — 화방 시트는 헤더만 |
| 엽축 휨 θ 측정값 | **0건** — 4점 정의는 있고 값이 없음 |
| 절대 PPFD | **없음** — 앱 측정 비율(0.92–1.24)뿐. 18개체에 **서로 다른 값이 9개**, 같은 줄 두 개체는 완전 교락 |
| 점등 시각 | **null**, 소급 불가 |

그래서 모든 실행에 `run_status = assumption_conditioned`,
`evaluation_status = evaluated_unaccepted` 를 달게 했고, **`accepted_for_domain` 은 금지**했습니다.
요청서 §3의 지시대로 **소프트웨어 통과기준과 생장 예측 정확도를 완전히 분리**했습니다(영어 §12 vs §13).

## 2. 광→탄소 사슬: 폐루프는 존재하지 않습니다

요청서 §2-7이 "현재 계산기에 없는 연결을 구현된 것으로 취급하지 말 것" 이라 했습니다. 다섯 연결을
전부 확인한 결과:

| 연결 | 상태 |
|---|---|
| ① 구조 → 소엽별 광 차단 | **구현·실행됨, 단 합성 기하에서만.** 실제 개체 `dwt_01` 에서는 광 단계 전체가 모든 값을 `unavailable` 로 반환 |
| ② 광 → 광합성(비직각 쌍곡선) | **구현·실행됨, 가상 입력에서만** |
| ①→② 어댑터 | **없음** — 광 표현과 탄소 표현을 잇는 운영 어댑터가 존재하지 않음 |
| ③ 탄소 → 기관 sink 배분 | **미연결** — 배분 엔진이 아예 없음 |
| ④ 배분 → 기관 생장량 | **미연결** — 생장 엔진은 **탄소를 모릅니다**: 2,309행에 carbon/assimilate 가 0회 |
| ⑤ 생장 → 다음 구조 | **미연결**, 의도적으로 차단 |

그리고 **금지된 형태가 이미 코드에 있습니다**: 생장 엔진의 예측 상태가
`surface_role = 'compound_envelope'` 로 태깅돼 있습니다. 광 쪽은 소엽별 삼각형을 올바르게 쓰는데,
생장 쪽이 복엽 포락면을 들고 있습니다. 3단계가 이걸 물려받지 않도록 명시하고 변경요청 CR-3으로
올렸습니다.

## 3. diaf024 vs Micro-Tom 분리

요청서의 지적이 맞습니다. 그리고 **diaf024 수치들이 실제로 디스크에 있습니다** —
`build/fsp_physiology_spec_20261003_01/sources/dwarf_dynamic_parameters.csv` 에 "model assumption",
"literature" 같은 출처 표시와 함께. 총 37개 항목을 분류했고 요약하면:

**재사용 가능(식 구조만, 계수는 재적합 필요)** — 기관 beta 생장 함수형, Thornley 비직각 쌍곡선
광합성, Q10 유지호흡, 탄소 버퍼 되먹임(Vanthoor 2011 형태), sink 배분식.

**사전값일 뿐, 보편 법칙으로 쓰면 안 되는 것** — 측지 랭크 1·2·7, 분지각 30°
(`BRANCH_INCLINATION,30`), 엽서각 137°(`COUNTER_CLOCKWISE_ORIENTATION,137`, 출처 표시가
"golden angle" 가정), 잎 경사 70°(`LEAF_ANGLE_D,70`), 주경 마디 상한 10, 화방 랭크 6–10, 화방당
8과(`FRUIT_PER_TRUSS,8`, "educated assumption"), T_base 5.7 °C, 잎·절간 beta 계수.

**오용 판정** — **ψ = 42.4 °Cd 는 `delay_between_fruit_appearance`** 입니다. 요청서 지적대로
**과실 출현 지연이며 엽 출현 간격(phyllochron)이 아닙니다.** 코드의 원 변수명이 그것을 그대로
증명합니다.

**적용 불가** — 측지 마디 상한 4 (측지를 이번 범위에서 제외하므로).

**우리 조건의 18.63 °Cd/일**도 `user_assumed` 입니다 — 26/22 °C·14/10 h 가 **설정값이고 로그가
아니며**, T_base 5.7 자체가 다른 품종 문헌값이기 때문입니다.

주의: **문헌 파일이 디스크에 없습니다.** diaf024·Butturini·Carvalho 2011·Martí 2006 를 전부 검색해도
없어서, 수치는 **요청서 본문을 출처로** 인용하고 전부 `literature_other_cultivar` 로 표시했으며
**원논문과 대조하지 못했다고 명기**했습니다.

## 4. 최소 실행 가능 모델(MVP)

지금 자료로 정직하게 만들 수 있는 것은 이 순서입니다.

1. **전제조건 게이트** — 영어 §11의 여섯 가지 차단 사유와 §0의 기록 부족을 보고하고 **예측값을 쓰지
   않고 종료**. 이게 오늘의 올바른 동작입니다.
2. **기준선 두 칸** — `tools/compound_growth.forecast()` 를 그대로 호출(persistence, recent change).
   코드 수정 없이 재사용 가능하지만, 아래 여섯 가지가 선행조건입니다.
3. **가정 대장(`forecast_assumptions.csv`)** — 쓰는 모든 매개변수를 `source_kind` + `source_ref` 와
   함께 한 행씩. 출처 없는 값은 **에러**로 처리.
4. **조건부 연속 변화** — 면적·길이 궤적을 구간값으로, 전부 `generated_candidate` + `user_assumed`.
5. **이산 사건** — 출현·화방·정지를 확률+구간으로, `provided_axes` 범위 안에서만.
6. **rolling-origin 하네스** — 미래 누설 0건을 증명하는 **삭제 동등성** 테스트와 함께.

### 기준선 재사용의 여섯 가지 차단 사유

1. **좌표계** — 두 계산기 모두 `coordinate_frame == 'board_mm'` 를 강제 검사하는데, 2단계 기본은
   `plant_local_mm` 이고 2단계 사양은 둘 사이 변환을 **금지**합니다(복원 불가). **가장 어려운
   구조적 장벽이고 사람이 결정할 문제**입니다.
2. **밀리미터 부재** — `validate_history` 가 `rachis_points_mm` 와 일치하는 `rachis_arc_length_mm` 를
   요구하는데 스케일이 없어 **상태 객체 자체를 만들 수 없습니다**.
3. **신원** — 확률 모델은 `identity_status != 'confirmed'` 인 상태를 거부하는데, phynotype2 연결은
   사람 검수 전까지 전부 `proposed` 입니다.
4. **일주 교락** — `recent_change` 는 축·범위 관측점이 동일한 두 날짜를 요구하고, 2단계는 위상이
   맞지 않으면 `unavailable_diurnal_confound` 를 냅니다. 점등 시각이 null이라 맞출 수 없습니다.
5. **구간 없음** — `compound_growth` 는 예측구간을 만들지 않아서 기준선 칸은 **적중률을 채점할 대상이
   아예 없습니다**.
6. **정확한 시각 일치** — 평가 대상 시각을 `observed_at` 문자열에서 **그대로 복사**해야 합니다.
   세션 날짜로 계획을 세우면 조용히 `unavailable` 행이 됩니다.

1·2번 때문에 오늘은 기준선에 **넣을 수 있는 입력이 없습니다.**

## 5. 필요한 시계열과 보정 절차

| 예측 대상 | 지배 조건 | 최소 요건 |
|---|---|---|
| 면적·길이 증가율 | 시점 수 | 기관당 위상 맞춘 **2회**(직선), **4–6회**(포화형 beta까지) / 개체 효과 분리는 **8–12개체**, 분리된 2그룹 |
| 엽 출현 간격 | **촬영 간격**(개수 아님) | 추정할 간격의 **1/3 이하** 간격 → 매일 또는 하루 2회, 위상 맞춰 **주경 정지까지**. 주 1회 시리즈로는 며칠 간격을 추정할 수 없음 |
| 화방 랭크 pmf | 개체 수 | 개체당 1추첨이므로 18개로는 부족 → **30–50개체**를 첫 화방까지 추적 |
| 주경 정지 | 개체 수 | 개체 생애당 1사건 → **30–50개체**를 종료까지. 18개 코호트로는 "선언된 규칙"까지만 |
| 방향 변화 | 선행조건 | 점등 시각 기록 + 회전 해 + **깊이 근거**(측면 사진 포즈 해 또는 보드 없는 3D). 시점만 늘려도 안 됨 |
| 굴곡 θ | 정의·정적 측정 | 평/휨 경계 확정을 위한 **정적 7건 이상** 먼저, 그 다음 측면 뷰에서 기관당 2회 |
| 예측구간 적중률 | 둘 다 | 수량·지평당 위상 맞춘 **5–10개 타깃**, 분리된 2그룹(예: 훈련 4–6 / 검증 4–6) |

보정 절차는 "기준선 → 가정 대장 → 조건부 궤적" 순서를 유지하고, 측정값이 들어오는 즉시 해당
매개변수의 `source_kind` 를 `user_assumed` → `measured` 로 올리되 **값은 새 관측으로만** 갱신합니다
(2단계의 상태 비승격 규칙과 같은 원칙).

## 6. 근거가 부족한 항목 (기본값으로 채우지 않은 것)

- 잎자루 삽입각 · 소엽 표면 기울기 · 소엽 굴곡 — **정의 자체가 없음**(2단계 사양에서 이미 지적).
  정의가 없으면 적합할 대상이 없습니다.
- 굴광성·굴중성 — 절대 PPFD 없음, 광의 **방향** 기술 없음(수평 비율 지도뿐), 깊이 근거 없음.
  광반응 기울기의 유효 n은 **9**(18 아님)이고 줄 단위로 교락돼 있습니다. **별도 연구 과제로**
  남겼습니다.
- 펼쳐짐(unfolding) — 기록 변수가 아예 없습니다. 주 1회 설계 주기보다 빠른 사건입니다.
- 낙엽·제거 — `manual_events.csv`·`organ_label_map.csv` 가 없어 **구조적으로 도달 불가**.
- 우리 해체 복엽의 **1차 소엽 7장** vs 문헌 "보통 5장(1·2번 잎은 3장)" — 랭크별 실측으로 판단할
  문제이고, 어느 쪽도 기본값으로 쓰지 않았습니다.

## 7. 측지(곁가지) 판단

**이번 범위에서 제외합니다.** 선호가 아니라 코드가 결정한 결론입니다 — 확률 엔진이
`provided_axes` 외의 범위를 **예외로 거부**합니다(`probabilistic_compound_growth.py:796-797`).
요청서 §2-9의 "넣지 않는다면" 분기를 택해 `topology_scope = 'provided_axes'` 와 전식물
`completeness = unavailable` 을 출력에 달게 했습니다.

같은 `if` 문이 **30일 지평도 함께 강제**합니다. [0, 30] 안의 **날짜 목록**은 지금도 되지만,
**다른 길이의 지평 목록**은 Codex의 코드 변경이 필요합니다(CR-1). 기준선 모델은 이미 지평 목록을
받으므로 두 칸의 지평을 따로 적게 했습니다.

## 8. 사람 결정이 필요한 것 (영어 §14와 동일)

1. **좌표계 게이트**(CR-2) — 보드 촬영을 요구할지, 잔차를 선언한 어댑터를 둘지, 게이트 문구를 바꿀지.
   **가장 어려운 장벽.**
2. 화분 테두리 내경 실측, 하루 점등 시각(지금부터, 소급 불가).

5. **18개 슬롯에 `plant_id` 부여** — 지금은 식별된 개체가 0개라 날짜 간 추적이 성립하지 않습니다.

7. 조건부 탄소 계산용 기준 PPFD 가정값, 또는 교정된 측정기.
