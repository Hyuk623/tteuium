Implementation brief before code changes, 2026-10-11. Requested by the user through `CODEX_FSP_EIGHT_CAPABILITIES_EXTENSION_PROMPT_2026-10-11.md`. No training, upload, remote job or messaging is authorized or needed.

## Verified starting behavior and authority

`tomato_fsp_pipeline.prepare_run/run/commit_step` consumes actual P1 fixture truth and produces one native trajectory. `vtc_development_native.rgg::simulate` owns light, age, mass and geometry. Current transport calls only `getAbsorbedPower`; black materials and a single bounce hide received/reflected/transmitted quantities. The public Twilight API exposes those quantities independently, but its terminal escape/truncation accounting must be inspected, not inferred by subtraction. Current schedules are duration-only. Imported triangles scale without changing initial posture. The Python water/element ledger is post-run prescribed bookkeeping and cannot constrain native growth.

Three statuses are mandatory: engineering implementation, real-input readiness and biological validation. All examples remain conditional; no empirical biological approval is implied. E6's age-to-posture law and E7's executable scientific contract are absent. Finish independently supported mechanics, and explicitly report those scientific gates rather than inventing their laws.

## Version and compatibility

Keep `fsp-integration-1` and `vtc-development-3` readable. Add an explicitly selected `extensions` object with `schema_version=fsp-extensions-1`; absent extensions preserve the existing mode. New tables/columns are required only in this mode and are bound into native completion/checkpoint hashes. New optional hook parameters never become required in old snapshots. No automatic activation from an available registry value. Record migration/active feature flags and the exact native model hash. Default-off behavior is tested against existing fixtures.
