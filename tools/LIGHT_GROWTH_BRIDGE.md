# Light inputs for growth and physiology consumers

This additive bridge exports current supported tissue photons and actual direct-light arrival moments. It does not predict growth, rotate a leaf toward a lamp, infer hidden tissue, or compute carbon. The optional core diagnostic callback exposes existing transport contributions without changing the scalar/side calculation. Production exports use that same-call stream and parity checks; they do not use lamp-center directions.

## Commands

Run from the project root with fresh directories under `build/`:

```powershell
python -X utf8 -m tools.light_growth_demo --out build/light_growth_example_new
python -X utf8 -m tools.light_growth_bridge audit --input build/light_growth_example_new/request.json --out build/light_growth_audit_new
python -X utf8 -m tools.light_growth_bridge export --input build/light_growth_example_new/request.json --out build/light_growth_package_new
python -X utf8 -m tools.light_growth_bridge validate --input build/light_growth_package_new
python -X utf8 -m tools.light_growth_bridge split --input build/light_growth_package_new --instance P1 --out build/light_growth_P1_new
python -X utf8 -m tools.light_growth_bridge schema
```

The demo creates artificial geometry, lamps, observations and review associations, runs deterministic direct transport, and checks two copies of one source. It does not execute native jobs. Its reviews and numbers are synthetic software fixtures, not real measurements. The bridge has no custom OS environment variables; inputs are explicit paths. It reuses current project/core loaders where those loaders consume project settings.

## Request JSON

Use schema `light-growth-1`, a nonempty `run_id`, and:

- `snapshots`: unique `geometry_snapshot_id`, paths `prepared_run` and `full_scene_results` from the existing hierarchy tool, timezone-aware `valid_from`/`valid_until`, `geometry_mode` (`observed` or `held_current_geometry_scenario`), source `board_frame_ids` keyed by every canopy instance, and optional actual `observed_at`. An optional `observed_at_by_instance` map overrides the shared timestamp, preserving distinct source observation clocks in hypothetical mixed-capture canopies; a null override stays unknown. Paths are relative to the request. A capture date does not supply observation time.
- `interval`: aware `start_at`, `end_at`. Snapshot windows cannot overlap. Missing windows remain explicit gaps.
- `schedule`: IANA `timezone`, explicit `provenance`, `fixed_optics_beam_spectrum=true`, and `fixtures` keyed by exactly the resolved fixture IDs. Each fixture has core `ScheduleSegment` objects (`start_hhmm`, `end_hhmm`, `output_fraction`, optional `electrical_input_w`), or null for unknown. The listed segments define a complete daily schedule, with zero outside lit intervals. Use a `00:00`–`24:00` segment with fraction 0 for an explicit full blackout. Empty lists are rejected as ambiguous. Fractions are photon output, never a linear power-to-PPFD conversion.
- `limits`: positive integer `max_transport_calls`, `max_receiver_emitter_pairs`, `max_schedule_minutes`. Each direct snapshot needs one additional full-scene core call; native imports need none. The minute-scan budget bounds UTC schedule evaluation. Boundaries split at exact geometry times and clock-minute schedule changes, including DST. Changing optics/beam/spectrum requires a separate prepared snapshot; these changes cannot be supplied as an undocumented dimmer response.
- Optional `compound_history`: the existing hashed `compound-observations-1` manifest. Optional `associations` explicitly joins snapshot, instance, session and optical compound to `compound_leaf_id`. Every association requires `review_status="reviewed"`, `evidence_path`, `evidence_sha256`, matching `geometry_sha256`, compatible `area_basis_id`, and independently declared `supported_area_m2`. Source plant, clock, frame and area must agree. Partial axes preserve scalar features but cannot become an observed whole rachis.
- Optional per-association `region_partition`: explicit `proximal_distal_boundary_mm` in the measured compound local frame. Requires a full observed axis and reviewed orthogonal transverse vector. Attachment is origin, +x is attachment-to-tip chord, +y is the reviewed transverse vector. Left is y<0, right y>0. Proximal/distal use x below/above the declared boundary. Boundary samples are unassigned; no default transverse axis or longitudinal boundary is invented.
- Optional per-association `coverage`: `coverage_status` (`partial`, `complete`, `unknown`), independently available `estimated_total_area_m2` and `coverage_fraction`, and a separate matching `evidence_path`/`evidence_sha256`. Unsupported completeness is never inferred from processing all input triangles. Regional rows do not inherit whole-compound completeness.

`tools/light_growth_schema.json` defines every output CSV column, type, unit, primary key and numerical policy. It was authored before the implementation. Numeric missing values are `unavailable` in CSV and null in JSON. `availability.json` records a reason for every unavailable numeric field using each row's `availability_id`. `__all__` denotes aggregation and `__unassigned__` denotes an unavailable identity; neither is a biological ID.

## Package and accounting

`package.json` retains immutable input/code/artifact hashes, canopy context, geometry validity, schedule, units, timestamps and distinct uncertainty scopes. `instance_map.csv` and `transforms.json` record reversible source-board/grow transforms. Matrices are derived from the existing authoritative helper. Translation affects points only; directions use rotation and angular second moments use `R B R.T`.

`light_samples.csv` contains actual direct quadrature points in grow and board frames, normals, one-sided m2 weights, fixture and clock-step IDs, normal/opposite/total incident and absorbed PPFD. `time_step_id=full_output` is a response coefficient, not a clock interval. Native leaflet means are never written as samples.

`compound_light_features.csv` contains leaflet, compound, plant and canopy aggregates. Flux is summed before dividing by supported area. Missing samples invalidate the full aggregate; separately named finite subtotals do not claim completeness. Quantiles use area-weighted inverse empirical CDF. Different coordinate-frame/region rows repeat selected scalar features for reporting: never sum them as extra tissue. Only whole-supported grow-frame rows are used for dose accounting.

Left/right and proximal/distal region rows preserve raw area/flux, unknown and unassigned support. Whole-supported compound-local rows carry signed first-minus-second flux differences and `(mean_first - mean_second)/(mean_first + mean_second)` contrasts. These describe supported current tissue; unequal/partial support is not a whole-leaf biological response.

`light_intervals.csv` records exact clock boundaries and per-fixture fractions. `light_dose.csv` integrates each interval's area-weighted mean PPFD and its separate instantaneous flux. Thus changing area does not multiply an entire dose by final area. Full doses/photons require complete requested-time coverage; partial supported doses and covered seconds stay separate. DLI is incident dose only for a complete declared local day. A DST day has its actual elapsed seconds. Both-face PPFD uses one-sided area; absorbed PPFD already includes absorptance once.

The shared join is `(run_id, scenario_id, geometry_snapshot_id, plant_instance_id, session_id, compound_id, time_step_id, backend, replicate)`, refined by entity, region/frame or sample/triangle/fixture. Sum either actual fixtures or `fixture_id=all`, never both. Never combine deterministic direct and native transport under one backend.

`consumer_mapping.json` maps reviewed source identity, board-frame **observed rachis direction**, supported area cm2 and area basis to the current compound contract. It keeps incident-light covariates separate. Physiology consumes actual time-resolved samples and durations, with externally supplied temperature, RH/VPD, CO2 and physiological contracts. Broadband PAR cannot supply blue-light or red/far-red channels.

The independent `tools/light_growth_consumer.py` reads the serialized schema/CSV, rechecks hashes, identities, transforms, time validity, fixture scaling, sample completeness, weighted scalar aggregation, time-integrated doses and observation joins. It does not import exporter arithmetic. A split is reporting-only: it retains the full canopy run, neighbor geometry hashes and shading. An isolated optical run must use a new scenario and actual recalculation.

## Native and readiness limits

Existing native scalar leaflet responses and replicate identities are retained. Combined-fixture native results can be scaled only when every actual fixture has the same known fraction in that interval. Unequal/unknown schedules are unavailable, with no guessed lamp split. Native side channels, spatial quantiles/regions and angular moments are unavailable. Native preparation/execution remains in the old opt-in tool; this bridge never starts GroIMP.

`compute_directional_features` remains a pure helper for explicit contributions. Production exports instead call `direct_light` with `DirectionCollector`, verify complete same-call PPFD and positive-normal sums, and export its actual F/M/B. Equal opposing sources retain B while the dominant direction is unavailable. Their mean vector is zero and concentration is zero; B/F remains available. Zero received flux keeps zero raw moments and unavailable normalized quantities.

Software package verification does not establish physical or biological accuracy. Known real snapshots still need reviewed metric surfaces, lamp inputs/calibration and compound evidence. Future CompoundLeaf envelopes remain excluded; no relative image area is converted to metric tissue, and no future growth/respiration parameter is populated.

## Adopted callback and export extension (2026-10-04)

`tools.light_direction_diagnostics.DirectionCollector` consumes the adopted `direct-angular-1` protocol. It validates complete fixture/path inventories and bounded ordered chunks, preserves zero versus unknown contributions, copies/reduces borrowed arrays before callback return, checks received/normal-side PPFD against the same call's `DirectLight`, and returns per-receiver F/M/B in grow coordinates. It does not trace rays. The bridge connects it to the existing full-scene calculation, preserving original receiver surfaces and background occlusion.

Read `tools/DIRECT_ANGULAR_CONTRACT.md` for the exact implemented signature, payload, lifetime, units, reasons and limits. Historical proposal handoffs remain unchanged. `tests/test_light_angular_transport.py` tests the actual producer; `tools/tests/test_light_angular_exports.py` exercises transport through export and independent consumption, including deliberately lost/duplicated chunks and rehashed wrong results. Supplied-chunk unit tests are additional protocol coverage.

The additive `light-growth-1` schema extension keeps existing column meanings. `light_samples.csv` adds global `receiver_index`, `arrival_path_unknown_count` and ten raw moment columns (`arrival_flux_umol_s`, M x/y/z, B xx/xy/xz/yy/yz/zz), all moments in umol/s and grow coordinates. Unknown inventory has unavailable count, not zero. All time samples retain full-output inventory counts; these describe transport completeness rather than lit path counts. `angular_diagnostics.json` records each snapshot's fixture/emitter inventory, received counts, chunks, configured limit and same-call scalar/normal parity tolerances. Direct capabilities now advertise implemented directions; Native still cannot supply them. Consumers require the exact bundled schema and hashes, so older packages are historical rather than silently migrated.

For each actual path use W=w*p with supported one-sided metric area w; sum F=sum W, M=sum W*u, B=sum W*u*u.T. Scale all ten components by the explicit per-fixture clock fraction before summing real fixtures. Feature rows normalize only after summation. Board and reviewed whole-compound local rows rotate M and B; translations affect sample positions only. Observed rachis fields remain separate. Unknown paths/schedules invalidate complete moments; no path is silently removed. The independent consumer recomputes raw sums, schedule scaling, rotations, regional partitions and normalization from serialized samples, checks F=area*PPFD, trace(B)=F and physical moment bounds, and verifies path/fixture/global-receiver inventory. Instance splits retain the full canopy inventory/context and original global indices.

```powershell
python -X utf8 -m tools.light_direction_diagnostics --out build/light_direction_core_audit_new
python -X utf8 -m pytest tools/tests/test_light_direction_diagnostics.py -q
```

The audit CLI reads the current core signature/hash without running a simulation or changing inputs. Its execution-verification flags remain false because this command alone cannot prove actual transport/export success; use the execution report and fresh validated package for that evidence.

## D9 light basis and daily unit clarification

DLI unit metadata was clarified on 2026-10-03: `dli_mol_m2_day` uses `mol/m2/day`, while generic `incident_dose_mol_m2`/`absorbed_dose_mol_m2` retain `mol/m2` and photon totals retain `mol`. This changes the schema hash, not numerical values or the complete-local-day gate. There is no extra division by 86400 or normalization of a DST day to 24 hours. Historical packages retain their original schema/hashes; new packages carry the clarified metadata.

For tissue light reporting, retain `light_dose.csv` identity/scope fields (`level`, `entity_id`, source/instance/session/compound, fixture, backend and replicate), time bounds/timezone/coverage, and `area_basis_id`. Join to time-resolved `whole_supported` grow-frame features for supported area and spatial completeness; join to real-fixture intervals for schedule evidence and to package geometry validity for the observed-versus-held-geometry scenario. An `all` aggregate uses the real fixture schedules, never a second `all` lamp. Incident tissue DLI is neither absorbed dose nor a reference sensor-plane value. The accepted D9 reference clarification below supersedes any earlier suggestion of selecting a tissue row for P3; P2 does not implement a biological light response.

## Adopted reference DLI clarification (Growth Science, 2026-10-04)

The accepted P3 light input is incident DLI at **one declared reference position and sensor plane**, over a complete local day, in mol photon m-2 day-1 (`mol/m2/day`). Its whole-plant **model scope** describes where P3 applies the covariate, not an average over plant tissue. Its reference `basis_id` must be distinct from every tissue `area_basis_id`. P3 owns its declared DLI applicability interval, out-of-interval rejection and separate c_DLI declarations per growth_curve. P2 supplies light and provenance only.

The optional request field `reference_dli={path,sha256}` accepts a separately produced, independently validated reference result. See [REFERENCE_DLI.md](REFERENCE_DLI.md) for measured logged/spot inputs and missingness. `reference_channel.json` records the original hashed source and copied `reference_dli/` result/CSV/audit. Available mapping includes the explicit associated plant IDs; it never applies a sensor automatically to every canopy instance. Missing inputs remain `reference_inputs_not_supplied`; failed or out-of-domain evidence is retained while usable value/basis/domain remain null. The capabilities value is `implemented_measured_logged_and_spot_schedule_simulation_readiness_only`, independent of one day's availability.

The independent package consumer revalidates the copied record against original hashed readings and domain evidence, separates the reference basis from every tissue basis, and checks the mapping. Rehashing a fabricated value does not make it valid. Splits preserve full canopy context, face evidence and the reference bundle. A reference associated with P1 remains identified as P1 in another instance's reporting split; it is not relabelled as that instance's measurement.

The measured producer integrates complete supported local-day intervals with explicit sample semantics, transition/gap policy and actual DST seconds. Unknown light is not darkness. P3 compatibility uses `tools.reference_dli_p3.map_single_day` with an explicit P3 evidence classification and a predeclared model contract. It changes only reference-light fields; kind/center/scale/coefficients and their domain binding remain frozen. Multi-day/scenario records remain valid producer records but are refused by this single-local-day mapping rather than assigned a fake representative date. No forecast is run.

L02 F/M/B still describe receiver-to-emitter illumination. P3 must reject directly binding arrival vectors, dominant direction, mean direction or moments as orientation parameters; **P3 owns enforcement**. Observed rachis direction is a separate channel. These outputs do not predict phototropism.

For any later P4 nonlinear leaf exchange, first sum simultaneous contributions from actual fixtures at the **same sample/patch and time**, then evaluate the selected exchange response. Existing time-resolved `fixture_id=all` samples already contain this sum; do not add those again to per-fixture rows, sum per-fixture photosynthesis, or average patches before applying a nonlinear response. Join one duration by run/scenario/snapshot/time/backend/replicate; repeated fixture interval rows do not repeat exposure. Incident and already-absorbed PPFD remain separate. No second absorptance factor is applied. D15-D20 resolve the dwarf-source consumer policy: absorbed PPFD, before_mito and evidenced adaxial_only. P4 owns both/abaxial refusal and coefficient-basis issue reporting; P2 leaves physical two-face sums intact.

## Reviewed biological face exposure (D20)

Optional `face_mappings` entries bind one `mapping_id` to the exact `geometry_snapshot_id`, `plant_instance_id`, `session_id`, `organ_id`, `leaflet_id`, `triangle_id` and `geometry_sha256`. Require `normal_biological_face` (adaxial or abaxial), `review_status=reviewed`, `reviewer`, `evidence_path` and `evidence_sha256`. The separate `face_mappings.json` preserves this evidence. Mesh winding or a source filename alone is not accepted as a biological review.

Every direct `light_samples.csv` row now includes nullable `normal_biological_face`, `illuminated_faces`, `face_mapping_id` and `face_source_ref`. The latter references `face_mappings.json#mapping_id`. For two known side PPFD values, strictly positive contributions on both faces mean `both`; on one face only they mean the mapped `adaxial_only` or `abaxial_only`. This is classification, with no new physical threshold, clipping, halving or optical calculation. No positive contribution, missing mapping or an unknown side produces an unavailable enum with a field-specific reason. Nullable strings use the existing `unavailable` CSV token; legacy required identity columns retain `__unassigned__`.

After per-fixture schedule scaling, sum side photons across actual fixtures, then classify the `all` row again. Opposite faces therefore remain both; a switched-off lamp does not preserve its previous full-output face label. Full-output spatial samples remain separately labelled as full output. The independent consumer checks against the original hashed request, reviewed geometry/evidence, and actual serialized normal/opposite-side sums. Native supplies no biological exposure samples.

## Optical geometry evidence extension (2026-10-05)

New exports carry `package.json::optical_geometry_contract = optical-geometry-evidence-1` and an additive `audit.json::optical_geometry` list keyed by geometry_snapshot_id. The existing light-growth-1 CSV/schema, request fields, numerical transport and D20 fields are unchanged. Historical artifacts keep their original hashes; they are not migrated in place. The new marker is required for exports recording the new helper in code_hashes. Pre-extension packages have no such marker; all normal freshness/schema checks still apply.

`tools.light_geometry_evidence.audit_surface(path, data_kind)` reads the existing board-frame triangle or rectangular-patch CSV. It reports geometric_computability (available/unavailable/invalid), field-specific missing science versus malformed input, source SHA256, variant/source/session/plant identities, shape assumption and supported one-sided area in mm2 and m2. Missing A2 location/shape is receiving_surface_position_unavailable / receiving_surface_shape_unavailable. Projected/hull area alone is projected_area_not_physical_receiving_surface. Exact reversed duplicate triangles remain duplicate_geometry_face, not a second leaf face. Partial evidence is never expanded into total leaf or plant area.

`python -X utf8 -m tools.light_geometry_evidence --geometry <csv> --data-kind synthetic|observed_geometry|hypothetical_layout --out <fresh_build_path>` writes geometry_audit.json without changing the source. Scientifically unavailable output exits 0 with its status/reasons; malformed geometry exits 1. No geometry is constructed from a proxy. Existing strict core loaders continue to refuse incomplete optical tables.

Bridge snapshot evidence additionally binds the prepared geometry/scene hashes, explicit board frame IDs, grow-frame placements and existing surface-review records. Review declarations are preserved, not upgraded to calibration proof. Geometric computability and diagnostic transport remain separate from physical_ppfd_eligibility=unavailable: independent scale, pose, supported area and optical validation are required. P1 must supply located vertices or a justified explicit shape, frame/scale/pose/coverage/identity evidence; a normal alone is insufficient. Botanical mapping still requires the separate D20 review and hashes, regardless of geometric winding, upward normal or top/ring ratio. The consumer reconstructs the geometry audit from hashed source files and rejects rehashed fabricated eligibility/area/review records and positive physical-validation claims.

Area weights come from triangle cross-products: mm2 * 1e-6 -> m2; an explicitly cm2 observation uses cm2 * 1e-4 -> m2 for the existing association check. The two rectangular-patch triangles tile one area. Two illuminated sides do not double that denominator. Flux = sum(area_m2 * PPFD); PPFD is obtained by dividing total flux by supported area, never by summing PPFD or dividing by a projected mask. Absorptance remains applied once. Actual receiver cosine and lamp visibility are already evaluated in transport; area-review G and camera-view occlusion lambda are never extra corrections.

Splits retain the full evidence list, geometry/placement context and neighbor shadows; only reporting rows are filtered. Reference-position measured DLI is independently supported and remains available even when plant physical eligibility is unavailable. An unplaceable plant table can be audited independently of the measured producer; it cannot form a tissue transport package. P3's multi-day/scenario mapping limitation remains unchanged. Area-review A1/A2 reporting priority, matching and calibration strategy remain pending scientific decisions; no estimator defaults or reconstruction campaign are adopted here.
