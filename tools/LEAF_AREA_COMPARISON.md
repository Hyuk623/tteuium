# Existing leaf area and surface comparisons

These tools consume saved evidence. They do not run segmentation, infer hidden leaf tissue, approve optical surfaces or validate biological growth.

## Projected image area

```powershell
python -X utf8 -m tools.leaf_area_compare --study build/leaf_area_implementation_20261003/study.json --out build/my_fresh_area_comparison
```

The study has schema `leaf-area-comparison-1`, an explicit `integration` object, `preview_max_px`, optional `measurements` directory and `cases`. Paths are absolute or relative to the study file. The existing supplied study is a dwt_test diagnostic example, not a default rig specification.

Each case identifies `case_id`, `plant_id`, `session_id`, `capture` (capture.json), `structure` (structure.json), `batch` (saved leaflet-mask batch), and `capture_style`. Optional `view_grouping` supplies `centre_board_mm`, `top_elevation_gt_deg` and `source`. The grouping threshold may be null (inactive); a missing reference cannot produce an elevation. Optional `movement` preserves source-reported groups/status; this tool does not estimate motion. The structure's declared capture hash must match the selected poses. Existing excluded views are retained as exclusions. Case IDs must be unique safe directory names.

`integration` requires `chunk_pixels`, `inverse_iterations`, `inverse_tolerance_px`, `relative_area_tolerance`, `absolute_area_tolerance_normalized` and `max_edge_subdivisions` (power of two, at least 2). These are numerical settings, not physical accuracy thresholds. Pixel centres are integer original-image coordinates; corners lie at +/-0.5 px. Distorted boundaries are subdivided until their inverse-projected areas converge and forward projection meets the supplied inverse tolerance. Invalid/unconverged pixels remain unavailable. Integration operates in chunks with no persistent cache.

`tools.leaf_area_geometry.normalized_pixel_areas` also accepts an explicit pixel footprint size in original coordinates. Batch comparison requires masks already restored to their declared original crop dimensions; it rejects implicit resizing. `photo_area_v2` retains the current mask-wise hull depth percentile and nearest-depth union semantics. A corrected projected proxy still has tilt, depth and occlusion limitations.

Outputs include original/mask previews, per-photo CSV, measured-group CSV, complete audit, source snapshots and a viewer. `projected_area_cm2` is unavailable when any union pixels lack depth/integration support. `supported_projected_area_cm2` reports the partial sum, with coverage counts. Empty supplied masks, no masks and unsupported masks are distinct. All pose, board and motion diagnostics remain visible.

Corrected traits and separate compatible calibration summaries are saved. Calibration is freshly fitted from measurement rows; a historical k is never imported. Estimator, integration policy, camera calibration, grouping policy and capture style must match within a fit. Dates come from explicit capture/linked growth metadata; conflicting dates fail. Validation remains grouped by plant and is not a passed physical-accuracy gate.

Existing `plant_traits.photo_area` and `plant_traits.plant_traits` callers retain legacy behavior unless `area_policy` is explicitly supplied. The opt-in plant function also requires `capture_style` and accepts `view_grouping`. Photo-level legacy fields retain their old meaning; `area_v2` holds the new result. Versioned plant summaries identify their estimator and keep legacy comparison values. `calibrate` refuses incompatible mixtures.

## Observed local surfaces

```powershell
python -X utf8 -m tools.leaf_surface_compare --study build/leaf_area_implementation_20261003/synthetic_flat_inputs/study.json --out build/my_fresh_surface_comparison
```

This example is explicitly synthetic. A surface study has schema `leaf-surface-comparison-1`, `evidence_kind`, `capture`, existing `points` and `contours` CSV paths, `fit_images`, disjoint `heldout_images`, existing `quality` thresholds, `minimum_abs_ray_plane_cosine`, `surface_policy` and `patches`.

Point/contour columns reuse `tools.leaf_light.annotations`. Each patch supplies `organ_id`, `leaflet_id`, `tissue_patch_id`, `identity_status`, `point_review_status`, `review_source` and `topology_review`. The first two review states must be `confirmed` for geometric comparison; topology must be `accepted` before existing surface auditing reports supported area. These flags must refer to actual reviewed evidence. They are not generated by the tool.

`quality` reuses `min_ray_angle_deg`, `max_point_error_px` and `contour_tolerance_px`. `surface_policy` reuses `coordinate_tolerance_mm`, `minimum_face_area_mm2`, `minimum_supported_views` and `maximum_pair_checks` from compound_surface. Do not copy synthetic settings into real physical acceptance criteria.

The baseline is existing fixed-pose triangulation and mesh. The plane candidate fits those observed 3D points and intersects the same rays with the fitted plane. Both are checked against independent held-out image observations when supplied. No held-out image means independent image validation unavailable. Curvature may make the plane candidate worse; lower complexity is not automatically more accurate. The curved candidate explicitly remains unavailable until Claude supplies its reviewed model/regularization/selection contract.

For holes, disconnected fragments or folded leaves, partition the observed tissue into explicit local charts. A patch may add `local_chart` with `point_ids`, an ordered `boundary_point_ids` ring and `hole_point_ids` (a list of ordered rings, explicitly empty when no holes). All IDs refer to the existing physical observations CSV. Each chart keeps a distinct `tissue_patch_id`; several charts may share the same organ/leaflet identity and may share boundary points. No point positions, boundaries or chart partition are inferred. The existing fixed-pose triangulation and compound_surface.local_patch_faces are reused for both the piecewise-linear baseline and plane candidate. Boundary-crossing triangles are excluded rather than inventing new observations, so coverage can be partial.

Explicit charts require `visible_support` per patch, using the existing raster support convention: `image_file`, `visibility` (`visible`, `occluded` or `unknown`), and `review_source`; visible entries also require `mask` and `mask_sha256`. Paths are relative to the study or absolute. Masks must match original calibrated image dimensions. Only fit-view masks constrain surfaces; held-out masks cannot leak into fitting/support selection. Occluded/unknown views remain recorded but do not contradict geometry. At least the supplied policy's visible-view count is needed for eligible area. Missing evidence is unavailable, not approval.

The legacy contour CSV remains supported for single-chart leaves without holes. Its `boundary_index`/`boundary_count` are not used to infer explicit chart rings. Full-face support and duplicate/intersection checks reuse compound_surface, including across charts. Normals remain unsigned; optical gates are unchanged. `chart_hole_inputs_01`, `chart_disconnected_inputs_01` and `chart_fold_inputs_01` under build/leaf_area_implementation_20261003 are synthetic examples only.

Outputs include candidate surface CSV, compound_areas.csv with capture date, patch_inventory.csv, local and global face audits, fit/held-out residuals, source hashes, snapshots and a 3D/reprojection viewer with original/visible-mask toggle. Missing capture dates remain unavailable. Candidate faces include failed/unreviewed faces for inspection; use audit eligibility rather than treating the CSV as approved optical input. No complete plant tissue area is inferred.

## Validation limits and remaining work

Correct arithmetic is not physical calibration. Existing dwt_test camera poses remain diagnostic. Real leaf surface comparison requires independently reviewed physical correspondences and supported boundary/interior observations. Whole-plant accuracy requires independent non-destructive area references and a reviewed acceptance protocol. The curved fitting contract and those real references are still open; no complete surface/accuracy delivery is claimed.

## Dimensionless area relative to the first labelled leaf

The user's selected convention is `relative_area = area_cm2 / reference_area_cm2`. The reference is the first supplied labelled leaf within each plant/session/date/area-method/area-scope/view group. Input order is authoritative; label names and height proposals do not establish biological leaf order.

```powershell
python -X utf8 -m tools.relative_leaf_area --areas build/relative_leaf_area_20261003/synthetic_areas.csv --out build/my_fresh_relative_area_result
```

CSV columns: `plant_id,session_id,capture_date,area_method,area_scope,view_id,label_id,area_cm2`. Allowed scopes are `measured_leaf_area`, `projected_mask_area`, and `supported_partial_surface`. Projected mask ratios require an explicit common view. Preserve separate methods and scopes; aggregate supported patches belonging to the same labelled leaf before supplying rows. Duplicate labels within a group are rejected.

Outputs are `relative_leaf_areas.csv` and `audit.json`. They retain absolute areas, reference identity/area, dimensionless ratios, status, and input hashes. Missing or zero reference area makes the group's ratios unavailable; no replacement reference is chosen. Missing other areas remain unavailable, while measured zero areas yield zero when the reference is positive.

The surface-comparison CLI also writes `relative_leaf_areas.csv` and includes ratios in its viewer/report. It sums globally eligible faces over patches sharing an organ/leaflet identity, separately for each estimator, then uses the first identity in the study's patch order as reference. This is a supported-partial-surface ratio, not inferred whole-leaf area. Ratio arithmetic does not establish physical accuracy or remove unequal-coverage bias.

The synthetic example areas 20, 30, 10 produce 1, 1.5, 0.5. These are demonstration values, not measurements from T1/T2/T3.

## Detection only before physical measurement

Use saved image detections without metric calibration, camera poses, hull depth, confirmed 3D correspondences or independent area measurements:

```powershell
python -X utf8 -m tools.detected_leaf_area --batch build/plants_dwt_test_20261002/plants/dwt_t1/masks --out build/my_fresh_detection_ratios
```

Default `--mode mask` counts all foreground pixels in each saved original-resolution mask, preserving holes and disconnected components. It reuses the saved candidate, sensitivity and any manual edits; review and visibility remain explicit. This reads cached predictions and runs no new model. Explicit `--mode bbox` calculates original box width times height as a separate box-occupancy proxy. It never silently replaces a missing mask with a box.

The output `relative_detected_leaf_areas.csv` contains `area_px2`, `reference_area_px2`, dimensionless `relative_area`, source label/image IDs, source review/visibility, availability and reference identity. `audit.json` records hashes, provenance, method and limits. The first manifest label in each image is fixed as reference, including an unavailable first entry; missing/rejected first masks do not trigger a substitute. Different photos get separate reference groups because stable cross-view identity is not established by annotation IDs. No per-image sums are presented as whole-plant tissue area.

Formula: `relative_area = foreground_pixel_count / first_label_foreground_pixel_count`. A positive reference is exactly 1. Missing/zero reference yields unavailable ratios. Unknown capture date is retained as unavailable; no date is inferred from filenames. Image-space ratios include depth, tilt, occlusion and detection error and are not physical tissue-area ratios. No `area_cm2` is fabricated.
