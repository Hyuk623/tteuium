## 일정 판단 지점

- 11/8: 기기 확보 일정 미정이면 녹화/fixture로 개발 지속. 실기기 완료를 주장하지 않는다.
- 11/22: 세그멘테이션 평가 미달 시 수동 표시/전문가 검토로 파일럿 경로 유지한다.
- 12/6: 관리 후보 기준 미확정 시 연말 완료 범위를 관찰 안내+추가 확인+기록+재확인으로 확정한다. 가지치기 추천은 보류한다.
- 정확도 및 허용 오제안 수치 등 평가 기준은 11/8까지 전문가와 정하고 이후 결과에 맞춰 낮추지 않는다.
- 공유 서버 운영 여부는 11/8까지 결정한다. 현재 GitHub Pages는 정적 체험 페이지이며 팀 공용 DB나 실시간 수집 서버가 아니다. 서버 선택·비용·접근 정책 확정 뒤 별도 배포한다.

## 연말 필수 인수 시나리오

온도·습도/이미지 수신 → 근거 있는 관찰 과제 제시 → 사용자가 대상과 확인 방법 이해 → 추가 확인/수행/보류 → 캘린더 기록 → 정해진 재확인. 카메라 분석 미달 시 수동 검토가 개입한 사실을 명시한다. 모든 결과에 실제/모의/사람/모델 출처를 유지한다.

## 지속 모의 입력

로컬 API가 실행 중일 때 저장소 루트에서:

```powershell
build/product-venv/Scripts/python -m product.device_contract.seed_demo --url http://127.0.0.1:8018 --live --interval 300
```

최초 14일 모의 이력을 준비한 뒤 온도·습도를 5분마다 DB로 전송한다. 대시보드는 30초마다 조회한다. 전송 실패 시 다음 주기에 재시도하며 실패 기간을 실제 측정값으로 메우지 않는다. PC 종료/절전 중에는 동작하지 않으며 재부팅 후 명령을 다시 실행해야 한다. 실측이나 적정 재배 조건을 의미하지 않는다. 성장/이미지는 초기 fixture이며 이 반복 전송은 센서 두 항목에만 해당한다.

30일 조회의 10,000건 제한을 고려해 기본 간격을 300초로 정했다(30일 약 8,640건). 고빈도 장기 수집 전에는 서버 집계/페이지 처리가 필요하다. GitHub Pages는 배포 시 생성한 정적 모의값이며 이 로컬 입력과 연결되지 않는다.
