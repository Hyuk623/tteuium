# 실제 온도·습도 센서 연결 준비

대시보드는 장치별 온도·습도와 실제/모의 출처를 표시한다. 기존 HTTP API에 장치를 등록한 후 전송하면 프런트엔드 교체 없이 표시된다. 현재 로컬 API는 loopback 단일 사용자용이며 인증이 없다. 이 문서는 로컬 게이트웨이 개발용 계약이다. 외부 기기 직접 연결과 공용 운영에는 인증·TLS·네트워크 및 장치별 접근 정책을 먼저 구현해야 한다. GitHub Pages는 센서 수신 서버가 아니다.

## 등록 순서

기본 주소 예: http://127.0.0.1:8018. 아래 JSON은 API 문서(/docs) 또는 게이트웨이 HTTP 클라이언트에서 보낸다.

1. POST /api/plants
```json
{"id":"plant-01","name":"우리 집 식물"}
```
2. POST /api/devices
```json
{"id":"sensor-01","name":"거실 온습도 센서","plant_id":"plant-01"}
```
3. POST /api/readings (Content-Type: application/json)
```json
{"schema_version":"1.0","event_id":"sensor-01-unique-event-id","device_id":"sensor-01","observed_at":"2026-10-28T09:00:00+09:00","source":"device","sensors":{"temperature_c":23.4,"humidity_pct":59.2}}
```

observed_at은 실제 측정 시각(시간대 포함)으로 교체한다. event_id는 새 측정마다 새 ID를 부여하고 재전송에는 같은 ID/내용을 사용한다. 동일 이벤트는 중복 저장하지 않으며 같은 ID의 다른 내용은 409로 거절한다. 미등록 장치는 404, 잘못된 단위 타입/습도 범위/미래 시각은 422를 반환한다. 온도는 섭씨, 습도는 상대습도 %이며 없는 값은 null, 0으로 대체하지 않는다. 밝기·수위는 전송할 필요 없다. 실제 장치는 모의 장치 ID를 재사용하지 않는다.

## 화면 확인과 인수

등록한 식물과 관측 장치를 선택한다. 현재값, 최근 5건, 최근 24시간 범위와 기간별 그래프에서 데이터 출처를 확인한다. 30초마다 화면을 조회한다. 마지막 측정이 5분 넘게 오래되면 최근 데이터 없음으로 표시한다. 장치가 꺼지면 이전 숫자를 새 값으로 바꾸지 않는다. 수신 상태는 마지막 측정에 기반한 상태이며 물리적 연결이나 농학적 정상 상태의 보증이 아니다.

실기기 연결 시: ①전송/저장/표시 값 대조 ②동일 이벤트 재전송 ③일시 중단·복구 ④서버 재시작 보존 ⑤센서/모의 분리 확인. 아직 실제 하드웨어 연결 검증은 하지 않았다.

## 지속 체험 방식

- 로컬: seed_demo --live --interval 300 이 HTTP API로 5분마다 모의값을 보내 DB에 저장한다. PC와 프로세스가 실행 중이어야 한다.
- 공유 Pages: 브라우저에서 매분 바뀌는 결정적 모의 환경 이력을 생성한다. 최근 24시간은 분 단위, 그 이전은 시간 단위 예시이며 과거에 수신/저장한 센서 이력이 아니다. 페이지가 다시 열리면 현재 시각 기준으로 재구성한다. 실제 서버 연결·지속 수집·팀 공용 저장을 뜻하지 않는다.
- 성장 지표와 이미지는 배포 당시의 예시 자료이고 실시간 분석하지 않는다. 사람의 관리 행동을 자동으로 만들어 넣지 않는다. Pages의 사용자 기록은 기존처럼 해당 브라우저에만 저장한다.
