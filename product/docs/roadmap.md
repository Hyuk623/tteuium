# 6주 개발 로드맵 — 관찰 중심 제품 MVP

현재 제공물은 각 주차의 초기 구현을 포함한 로컬 MVP입니다. 아래 일정은 도메인 검토와 실제 기기 검증을 포함한 후속 6주 계획이며, 하드웨어 검증까지 완료했다는 의미가 아닙니다.

| 주차 | 작업 및 산출물 | 완료 기준 | 도메인 전문가의 최소 결정 |
|---|---|---|---|
| 1 | Product/Device Contract v1, Growth·Environment·Light·Fruit·Condition·Action 스키마, 출처/지원 상태 정의 | 단위·시간대·누락·재전송 계약 검토, 미지원 값은 null/unavailable, 판단 금지 목록 문서화 | **현재 신뢰하고 보여줄 수 있는 지표**와 출처/단위; **판단 금지 영역** 초안 |
| 2 | Mock sensor → DB → API, 14일 이력, SQLite 저장/재시작 검증 | 모의값 명시, 잘못된 값 거절, 중복 허용/충돌 거절, 식물 간 데이터 격리 | 1주차 지표 표시 방식의 오류만 확인; 새 농업 임계값 요구 없음 |
| 3 | Dashboard Home/Environment, 기간 선택, 시간 그래프, 누락/오래된 관측 표시 | 가정 사용자에게 모의/실제 출처와 시각이 보이고 환경 4개 지표를 읽을 수 있음 | ‘정상’, ‘적정’ 등 판단으로 오해되는 문구가 없는지 확인 |
| 4 | Growth, 이미지 비교, tomato3d Adapter, 출처·시나리오별 그래프 | 실제 plant_light.csv와 fixture 구분, 초장/캐노피 미출력은 unavailable, 수동 관측 분리 | 표시 가능한 지표 최종 선택; **향후 추가할 주요 생육 이벤트** 우선순위 |
| 5 | Action Log 6개 관리 유형, Observation→Evidence→Check→Action 안내 | 저장 후 재시작해도 기록 유지, 근거/기간/출처 확인 가능, 진단·자동 처방 없음 | 판단 금지 목록과 안내 문구 검토; 재배 기준 전체 확정은 불필요 |
| 6 | 실제 device 연결, 통합 테스트, 데모 및 인수 문서 | 실제 이벤트로 단위·시간·누락·재접속·중복·오래된 값 검증, 모의/실제 분리 데모; 기기 미도착 시 모의 검증까지만 명시 | 실제 시연의 지표/문구 최종 확인; 농학적 효능 검증은 별도 연구 |

## 도메인 전문가에게 지금 요청할 세 가지

1. **현재 신뢰하고 보여줄 수 있는 지표:** 지표 이름, 단위, 출처(사람/센서/모델), 사용자에게 보여도 되는 설명. 초장·잎 면적·캐노피를 모두 승인할 필요는 없습니다.
2. **현재 판단 금지 영역:** 질병, 영양결핍, 수분 스트레스, 정상/적정 판정 등 아직 확정하거나 추천하면 안 되는 항목.
3. **향후 추가할 주요 생육 이벤트:** 개화·착과·첫 수확 등 우선순위 2~3개와 수동 기록부터 시작할지 여부.

## 기기 담당자의 별도 결정

센서/컨트롤러 모델, 전송 방식, 샘플 메시지, 단위/보정, 측정 주기, 장치-식물 매핑, 시간 동기화, 인증과 재전송 정책을 기기 담당자가 정합니다. 도메인 전문가에게 모든 농업 기준이나 하드웨어 규격을 한 번에 요구하지 않습니다.

## 이후 확장

PostgreSQL 마이그레이션과 백업/복원, 인증·다중 사용자, 이미지 업로드/보관, 연구 작업 스케줄링을 실제 서비스 단계에서 진행합니다. 열매/질병 분석·관리추천·자동제어는 별도 검증과 승인된 계약이 확보되기 전까지 보류합니다.
